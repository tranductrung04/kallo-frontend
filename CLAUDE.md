## Commands

Run from repository root:

```bash
npm install
npm run typecheck
npm run self-check
npm run start
npm run android
npm run ios
npm run copy-assets
```

- `npm run start` launches the Expo development server.
- `npm run android` and `npm run ios` launch Expo on the corresponding platform.
- `npm run typecheck` runs strict TypeScript checking with `tsc --noEmit`.
- `npm run self-check` runs assertion-based checks for phases 1 through 7.
- Run one phase check directly with `node scripts/phase7-self-check.js` (replace script name as needed).
- `npm run copy-assets` copies source files from `res/` into `src/assets/images/`.
- No lint script or test runner is configured; there is no production build script in `package.json`.

## Architecture

- Expo SDK 52 + React Native 0.76 + TypeScript. `App.tsx` is the entry point and composes gesture handling, safe-area context, theme, auth, offline sync, system, and domain providers before rendering `RootNavigator`. Preserve provider order when a provider consumes another provider.
- `src/navigation/RootNavigator.tsx` owns the auth-driven root flow: loading splash, `AuthNavigator`, `OnboardingNavigator`, or the signed-in stack. `MainTabNavigator.tsx` owns the five tabs (Home, Diary, AI Scan CTA, Report, Profile); root stack screens host global flows, scanners, meal plans, assistant, activity, gamification, notifications, and reminders.
- `src/navigation/types.ts` is the source of truth for typed root, auth, onboarding, and tab route params. Update it when adding or changing routes.
- Code is feature-first under `src/features/`. Each domain keeps its types, utilities, provider/state, components, and screens together: auth, profile, nutrition, activity, meal-plan, assistant, report, gamification, and system. Keep domain logic out of navigators and shared components.
- Domain providers use AsyncStorage for local persistence and expose typed hooks. Nutrition, activity, meal-plan, gamification, and system state support local-first UI and best-effort API calls. Auth checks token/profile state and supports the local demo account path. `src/services/api/client.ts` attaches JWT access tokens and coordinates one concurrent `/auth/refresh` retry; `EXPO_PUBLIC_API_URL` overrides its default `http://localhost:8080/api`.
- `src/services/offline/` owns the client-UUID sync queue. `OfflineSyncProvider` persists queue state, tracks online/syncing state, and retries pending or failed items through `syncManager.ts`; `OfflineBanner` surfaces status globally.
- `src/components/common/` is the reusable UI kit. Components consume `useTheme()` and use typed props. `src/theme/` contains light/dark tokens for colors, typography, spacing, radii, and shadows; theme selection persists through AsyncStorage.
- `src/assets/images/index.ts` is the typed asset registry. `res/` is the source asset directory; copied app-local files are generated by `npm run copy-assets`. Keep registry entries and source files in sync.
- `@/*` resolves to `src/*` through matching Babel and TypeScript configuration. `app.json` defines Expo identity, portrait orientation, automatic system UI style, camera/image permissions, and Android/iOS bundle identifiers.
